# Bybit 선물 RR 툴 — 설계 문서

- 작성일: 2026-10-18
- 원본 요구사항: `2026-10-18-original-request.md` (사용자 작성, 이 문서의 상위 권한)
- 진행 방식: 사용자가 질문을 생략하고 "바로 시작"을 선택. 아래 "결정 사항"은 모두 빌더(Claude)의 판단이며 사용자가 승인한 내용이 아니다.

## 1. 의도

사용자가 원하는 순간 LONG/SHORT를 누르면 그 순간의 최신 체결가를 엔트리로 고정하고, 가격 구조(현재 시간봉의 급격한 캔들 꼬리, 상위 시간봉의 확정 스윙)로 SL·TP를 제안한다. RR은 결과로 계산될 뿐 목표가 아니다. 유저는 SL·TP를 드래그나 입력으로 고치고, RR·손익률은 즉시 갱신된다. 실제 주문이 아닌 가상 시나리오다.

## 2. 목표 / 비목표 / 반목표

- 목표: 원본 요구사항 1~9절 전체를 MVP로 구현. 사용자가 확정한 시장은 **Bybit USDT 무기한 선물(category=linear)**.
- 비목표(v1 제외): 엔트리 수정, 다중 시나리오, 수량·금액 손익, 수수료·슬리피지·레버리지 반영, 실제 주문.
- 반목표(동작해도 실패로 보는 것):
  - 엔트리 이후 데이터가 SL/TP 자동 선정에 섞이는 것
  - 목표 RR에 맞춰 TP를 역산하거나, 무효한 자동값을 설명 없이 다른 값으로 바꾸는 것
  - SL을 고쳤는데 TP가 움직이는 것(반대도 동일)
  - 오래된 가격으로 시나리오가 생성되는 것
  - 데모 데이터가 실데이터처럼 보이는 것

## 3. 데이터 공급원 사실 (Bybit V5 공식 문서, 2026-10-18 확인)

- REST 캔들: `GET /v5/market/kline` — interval `1,3,5,15,30,60,120,240,360,720,D,W,M`, limit 1~1000(기본 200), 응답 `result.list`는 최신순, 각 항목 `[startTime, open, high, low, close, volume, turnover]` 문자열. 미확정 캔들의 close는 마지막 체결가. 응답 최상위에 서버 시각 `time`(ms).
- REST 종목: `GET /v5/market/instruments-info?category=linear` — limit 최대 1000(기본 500), `nextPageCursor` 페이지네이션, 기본으로 `Trading`과 `PendingOpen` 반환. `priceFilter.tickSize`, `quoteCoin`, `contractType`, `status` 사용.
- WS: `wss://stream.bybit.com/v5/public/linear`, `{"op":"subscribe","args":[...]}`, ping `{"op":"ping"}` 권장 20초 간격, pong 응답 `{"op":"ping","ret_msg":"pong","success":true}`.
- WS `kline.{interval}.{symbol}`: 1~60초마다 푸시, 필드 `start,end,interval,open,close,high,low,volume,turnover,confirm,timestamp`, `confirm=true`면 확정.
- WS `publicTrade.{symbol}`: 실시간, `data`는 체결 시각 오름차순, 필드 `T`(체결 ms), `p`(가격) 등.
- WS `tickers.{symbol}`: linear 100ms, snapshot/delta, delta에서는 바뀐 필드만 옴.
- 미확인: 브라우저에서 REST 호출 시 CORS 허용 여부, 한국 IP 접속 가능 여부. (빌드 환경에서 Bybit 접속이 차단되어 확인 불가)

## 4. 결정 사항 (빌더 판단 — 사용자 확인 필요)

| # | 항목 | 결정 | 틀렸을 때 비용 |
|---|---|---|---|
| D1 | 종목 범위 | Bybit linear 중 `quoteCoin=USDT`, `contractType=LinearPerpetual`, `status=Trading` | 필터 한 줄 수정 |
| D2 | REST 경로 | 브라우저 → Vite 개발 서버 프록시 `/bybit-api` → `https://api.bybit.com` (CORS 미확인 회피). WS는 직접 연결. 둘 다 `src/config.ts`에서 변경 | 설정 변경 |
| D3 | 엔트리 가격 | `publicTrade`의 최신 체결가. 아직 체결 수신 전이면 `tickers.lastPrice`. 가격 시각은 거래소 시각 | 엔트리 정의 변경 |
| D4 | 끊김/오래됨 판정 | 소켓이 열려 있고 마지막 메시지(퐁 포함)가 15초 이내면 정상. ping 10초 간격. 최신 가격의 거래소 시각 기준 나이가 60초 초과면 오래된 가격으로 보고 생성 차단. 두 값 모두 설정 가능 | 임계값 조정 |
| D5 | 확정 캔들 판정 | 캔들 시작+시간봉 길이 ≤ 기준 시각(엔트리 가격의 거래소 시각) 이고, 데이터가 확정 상태(WS `confirm=true`, REST는 서버 시각 기준 종료된 캔들)인 것만 사용 | 경계 캔들 1개 차이 |
| D6 | ATR | Wilder(RMA) 방식, 첫 TR = 고가−저가 (TradingView `ta.atr`와 동일). 설정에서 SMA 선택 가능 | 점수 순위 변화 |
| D7 | "직전 ATR" | 후보 캔들 i를 제외한 i−1까지의 ATR. ATR을 계산할 수 없는 후보와 ATR=0 후보는 건너뜀. 유효 후보 0개면 "데이터 부족" | — |
| D8 | 스윙 판정 | 고점: 왼쪽 N개보다 엄격히 높고 오른쪽 N개 이상(≥). 저점 대칭. N은 "스윙 판별 봉 수" 하나로 좌우 공통(기본 2). 확정 시점 = 오른쪽 N번째 봉 마감 | 동일 고점 처리 |
| D9 | TP 모드 | 기본 = 명세 그대로 "가장 최근 확정 스윙"(엔트리 반대편이면 무효). 옵션 = "엔트리 너머의 가장 최근 확정 스윙" | 무효 빈도 |
| D10 | 상위 시간봉 기본값 | 1→15, 3→15, 5→60, 15→60, 30→240, 60→240, 120→D, 240→D, 360→D, 720→W, D→W, W→없음. 월봉(M)은 길이가 일정하지 않아 제외 | 설정 변경 |
| D11 | 상위 시간봉 데이터 | 클릭 시점에 REST로 최대 1000개 조회 후 기준 시각으로 필터 | 클릭 후 TP 표시까지 수백 ms |
| D12 | 덮어쓰기 방지 | 활성 시나리오가 있을 때 LONG/SHORT를 누르면 엔트리를 잡지 않고 "먼저 종료하거나 삭제" 대화상자만 띄움. 종료 후 다시 눌러야 새 엔트리 생성(오래된 엔트리 방지) | 클릭 한 번 추가 |
| D13 | 종료된 시나리오 | 종료 시점에 박스 오른쪽 끝과 손익 수치를 고정해 계속 표시. 새 LONG/SHORT는 대화상자 없이 종료된 것을 대체 | — |
| D14 | 시간봉/종목 전환 | 같은 종목이면 모든 시간봉에서 선·박스 표시(왼쪽 끝은 생성 시각이 속한 봉). SL 캔들 강조는 생성 시간봉에서만. 다른 종목이면 숨기고 상단에 "활성 시나리오: 종목" 안내 | — |
| D15 | 박스 오른쪽 끝 | 최신 봉 + 10봉(설정 가능) | — |
| D16 | 색 | 캔들 상승 초록·하락 빨강(글로벌). 수익 영역 반투명 초록, 손실 영역 반투명 빨강 | 테마 변경 |
| D17 | 표시 항목 | 레퍼런스처럼 틱 수 표시. 수량·금액은 표시하지 않음 | — |
| D18 | 시간 표시 | 브라우저 현지 시각(한국에서는 KST) | — |
| D19 | 드래그 | 선/핸들 6px 이내에서 시작. 드래그 중 차트 이동·확대 비활성, 놓으면 복구. 엔트리를 넘어가도 막지 않고 무효 사유 표시. 가격은 가장 가까운 틱으로 스냅 | — |
| D20 | 수동 수정 상태 | 사용자가 한 번이라도 수정하면 값이 자동값과 같아도 "수동 수정" | — |
| D21 | 저장 | localStorage `rrtool.v1.state`(시나리오·선택 상태), `rrtool.v1.settings`. 스키마 버전 불일치·손상 시 무시하고 초기화 | 새로고침 시 시나리오 소실 |
| D22 | 데모 | 시드 고정 합성 데이터, 종목명 `DEMO-` 접두사, 화면에 항상 "DEMO 데이터" 배지, 연결 끊기 시뮬레이션 버튼 | — |

## 5. 구조

- `src/core/`: 순수 함수 — 시간봉, 가격/틱, RR 계산, ATR, 급격한 캔들, 스윙, 자동 선정, 시나리오 상태, 저장, 신선도
- `src/data/`: 공급원 인터페이스, 캔들 저장소, Bybit 어댑터(파싱·소켓·REST), 데모 어댑터
- `src/chart/`: 박스 기하·히트 테스트·드래그(순수), Lightweight Charts 연동(프리미티브·가격선·마커)
- `src/ui/`: 상단바, 패널, 대화상자, 앱 연결
- 차트 라이브러리: Lightweight Charts 5.2 (Apache-2.0, 시리즈 프리미티브로 커스텀 도형). 드래그는 직접 구현.
- 빌드/테스트: Vite 8, TypeScript, Vitest 5(단위), Playwright + 번들 Chromium(E2E, 데모 데이터)
