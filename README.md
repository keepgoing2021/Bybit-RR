# RR 박스 — Bybit 선물 손익비 시나리오 차트

LONG 또는 SHORT를 누른 순간의 최신 체결가를 엔트리로 고정하고, 가격 구조로 SL·TP를 제안하는 개인용 웹 차트입니다. SL·TP는 차트에서 끌거나 직접 입력해 고칠 수 있고, 손익비(RR)·손익률은 즉시 다시 계산됩니다. 실제 주문을 넣지 않는 가상 시나리오 도구입니다.

- 시장: **Bybit USDT 무기한 선물** (category=linear, 거래 중인 USDT 무기한 종목만)
- 원칙: 목표 RR로 TP를 역산하지 않습니다. SL·TP는 가격 구조로 정하고 RR은 결과로 계산합니다.

## 실행

필요: Node.js 22.12 이상

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다.

- 데모 데이터로 보기: http://localhost:5173/?source=demo (화면 위에 "데모 데이터 (실제 시세 아님)" 표시)
- 상단의 "데이터" 선택으로 Bybit/데모를 바꿀 수 있습니다.

### Bybit 연결 먼저 확인하기

```bash
npm run check:bybit            # BTCUSDT
npm run check:bybit -- ETHUSDT # 다른 종목
```

종목 정보, 15분봉 200개, 웹소켓 구독·퐁·체결·캔들·티커 수신을 항목별 PASS/FAIL로 보여줍니다. 하나라도 실패하면 종료 코드 1입니다.

## 사용 흐름

1. 상단에서 종목, 차트 시간봉, TP 기준 상위 시간봉을 고릅니다.
2. LONG 또는 SHORT를 누르면 그 순간의 최신 체결가가 엔트리로 고정됩니다. 연결이 끊겼거나 가격이 오래됐으면 버튼이 잠기고 이유가 표시됩니다.
3. SL: 현재 시간봉에서 엔트리 시점 이전 확정 캔들 중 가장 급격한 캔들의 꼬리 끝(LONG 저가 / SHORT 고가).
4. TP: 상위 시간봉에서 엔트리 시점에 이미 확정된 가장 최근 스윙 고점(LONG) / 저점(SHORT).
5. 박스: 초록은 수익 구간, 빨강은 손실 구간. SL·TP 선이나 왼쪽 네모 핸들을 끌어 고칩니다. 끄는 동안 차트는 움직이지 않습니다.
6. 오른쪽 패널에서 가격을 직접 입력할 수 있고(호가 단위로 맞춤), "자동 설정으로 복원"은 생성 당시의 자동값으로 돌아갑니다(다시 분석하지 않음).
7. 활성 시나리오가 있을 때 LONG/SHORT를 다시 누르면 덮어쓰지 않고 확인창이 뜹니다. 기존 것을 종료하거나 삭제한 뒤 다시 누르면 그 순간 가격으로 새로 만듭니다.
8. 새로고침해도 시나리오와 수정값이 남습니다(브라우저 localStorage).

자동값이 유효하지 않으면(예: LONG인데 SL 후보가 엔트리 이상) "유효한 자동 SL/TP 없음"과 이유를 표시하고 비워 둡니다. 다른 값으로 몰래 바꾸지 않습니다.

## 선정 이유

### 차트: Lightweight Charts 5.2.1 (TradingView)

- 라이선스 Apache-2.0, 무료. 라이선스의 저작자 표시 요건은 차트 왼쪽 아래 TradingView 로고(기본값)로 충족합니다.
- 시리즈 프리미티브로 박스·라벨·핸들을 직접 그릴 수 있고, 실시간 캔들 갱신을 지원합니다.
- 가격선 드래그는 기본 제공이 아니라 직접 구현했습니다(`src/chart/drag.ts`). 끄는 동안 차트 이동·확대를 끄고, 놓으면 다시 켭니다.
- 데이터 공급은 하지 않으므로 시세 연결은 따로 붙였습니다.

### 시세: Bybit V5 퍼블릭 API

- 무료, API 키 불필요. 사용자가 거래하는 Bybit 선물 종목과 호가 단위(tickSize)를 그대로 씁니다.
- REST: 종목 정보, 캔들(요청당 최대 1000개). 웹소켓: 체결(실시간), 티커(100ms), 캔들(1~60초 간격).
- 엔트리는 캔들 종가가 아니라 체결 스트림의 최신 가격을 씁니다. 캔들 푸시는 최대 수십 초 간격이라 엔트리가 늦어질 수 있기 때문입니다.
- 같은 이유로 차트의 마지막 캔들도 체결이 들어올 때마다 갱신합니다. 캔들 푸시가 오면 Bybit 값으로 다시 맞춥니다. 체결로만 만든 임시 캔들은 '미확정'이라 자동 SL·TP 선정에는 쓰지 않습니다.
- 제약: 웹소켓 연결은 도메인당 5분에 500회 이하. 브라우저에서 REST를 직접 부를 때 CORS가 허용되는지는 확인하지 못해서, 개발 서버가 `/bybit-api` 경로로 중계합니다(`vite.config.ts`). 그래서 `npm run dev`(또는 `npm run preview`)로 실행해야 합니다.
- 공급원은 `src/data/provider.ts` 인터페이스 뒤에 있어 다른 거래소로 바꿀 수 있습니다.

## 초기 가정 (확정 전략 아님, 화면의 "자동 제안 설정"에서 변경)

| 항목 | 기본값 |
|---|---|
| 급격한 캔들 탐색 범위 | 직전 확정 캔들 50개 |
| ATR | 14, Wilder 방식(TradingView `ta.atr`과 동일). 단순평균 선택 가능 |
| 급격함 점수 | 고저폭 ÷ 그 캔들 직전까지의 ATR, 동점이면 최근 캔들, 양봉·음봉 구분 없음 |
| SL 버퍼 | 0틱 |
| 스윙 판별 | 좌우 각 2봉. 고점은 왼쪽보다 엄격히 높고 오른쪽 이상 |
| TP 스윙 선택 | 가장 최근 확정 스윙 (옵션: 엔트리 너머의 가장 최근 스윙) |
| 상위 시간봉 기본값 | 1·3분→15분, 5·15분→1시간, 30분·1시간→4시간, 2·4·6시간→일, 12시간·일→주 |
| 박스 연장 | 최신 봉 + 10봉 |
| 연결 지연 판정 | 15초간 메시지 없음 |
| 가격 유효 시간 | 마지막 체결 60초 이내 |

그 밖의 결정(엔트리 정의, 확정 캔들 판정, 덮어쓰기 방지 방식 등)은 `docs/superpowers/specs/2026-10-18-bybit-rr-tool-design.md`의 결정 사항 표에 이유와 함께 적었습니다.

## 표시 수치

- 위험 거리 = |엔트리 − SL|, 보상 거리 = |TP − 엔트리|, RR = 보상 ÷ 위험 (표기 1:X)
- 현재 R: LONG (현재가 − 엔트리) ÷ 위험 거리, SHORT (엔트리 − 현재가) ÷ 위험 거리
- 손절률·목표 수익률 = 각 거리 ÷ 엔트리. 틱 수도 함께 표시
- 수수료·슬리피지·레버리지는 반영하지 않은 가격 기준 수치입니다. 수량을 입력받지 않으므로 금액 손익은 표시하지 않습니다.

## 구조

```
src/core/     판단 로직(순수 함수): ATR, 급격한 캔들, 스윙, 자동 선정, RR 계산, 시나리오, 저장, 신선도
src/data/     공급원: Bybit(REST·웹소켓·재연결), 데모(시드 고정 합성 데이터), 캔들 저장소
src/chart/    박스 좌표·히트 판정·드래그(순수), Lightweight Charts 연결
src/ui/       화면 구성과 상태 연결
tests/unit/   단위 테스트 (Vitest)
tests/e2e/    브라우저 테스트 (Playwright) + 가짜 Bybit 서버
```

## 테스트

```bash
npm test                         # 단위 테스트
npx playwright install chromium  # 처음 한 번
npm run e2e                      # 브라우저 테스트 (데모 데이터 + 가짜 Bybit 서버)
```

검증 결과와 직접 확인하지 못한 항목은 [docs/verification.md](docs/verification.md)에 있습니다.

## 알려진 한계

- 실제 Bybit 서버 연결은 개발 환경에서 차단되어 확인하지 못했습니다. `npm run check:bybit`로 먼저 확인하세요.
- 시나리오는 이 브라우저의 localStorage에만 저장됩니다. 다른 기기와 공유되지 않습니다.
- 활성 시나리오는 하나만 관리합니다. 엔트리 수정, 수량·금액, 수수료 반영은 v1 범위 밖입니다.
- 월봉은 길이가 달라 지원하지 않습니다.
